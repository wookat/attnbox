# Handoff context — attnbox

按 Company OS 交接上下文制度维护；换会话/换负责人时先读本文档。最后更新：2026-08-04（ROUND-666）。

## 项目一句话

跨"本地 CLI agent + 云端 agent"的统一注意力收件箱：不管 agent 跑在哪里，"哪个在等我、等我做什么（审批/回答问题/审 PR）"聚合成一个视图。

## 日常循环（当前运作方式）

1. 每轮（ROUND-N）轮换主驱动维度：真实测试 / UX 走查 / 前端视觉 / 竞品调研 / 用户与数据分析 / 文档新鲜度。
2. 有 P0/P1 → 修复 + focused tests + changeset（包行为变更时）；无 → 纯文档 GAP 轮。
3. 每轮产出 `docs/gap/GAP-ROUND-N.md`，独立分支 + PR，CI 绿后由总负责人合并。
4. 文档 PR 合并后重建官网；changeset 累积到值得发版时报总负责人出版本 PR。
5. 发布顺序 core→collectors→daemon→cli，逐包 `pnpm pack` + `npm publish <tarball>`；发布后干净环境回归 + GitHub Release。

## 关键设计事实（容易踩的坑）

- Devin 采集：全量分页爬取（100/页，深页 10 并发批，硬上限 10,000，30s 深页缓存）；云状态权威透传，5 分钟 stale-working 上限仅本地启发式适用。
- Devin waiting 详情：一次 collect 取全（顺序批，每批 10 并发，`updated_at` 缓存）——round-111 修复，勿回退为每周期条数上限（一次性 `ls` 永不补齐）。
- a11y 审计要覆盖交互态：round-117 的激活 tab 徽章、round-119 的内联代码底色都是默认态审计漏掉的（axe/Lighthouse 只测默认 tab/白底就会漏）。round-663 补充：状态依赖违规——已 ack 卡片曾用 opacity-50 整体变暗使卡内文本跌破 AA（最差 2.35:1），往轮 0 违规只因窗口内恰无已 ack waiting 卡在屏；已改 grayscale（去饱和保亮度，对比度与未变暗态一致），卡片变暗勿回退为 opacity。3k done 卡上直接跑 axe 会耗尽本机内存（round-147）：done 态固定审前 60 卡（覆盖全部卡片变体）。
- webhook/浏览器通知：id 仅在观测到非 waiting 后才离开已通知集合（防采集器抖动风暴，rounds 71/81）。
- `--host` 必须 token（`ATTNBOX_TOKEN`），API/SSE 全面 401 门禁（rounds 29/84 负例契约）。
- doctor 的 GitHub 探活走 review-requested 搜索端点，不能用 `/user`（App token 会 403，round-94）。
- 离线快照走 localStorage（round-79 重构过写路径，勿回退为每 tick 同步写；round-125 起恢复也是惰性的——SSE 快照先到就跳过缓存解析，勿回退为启动即解析）。
- 通知探针假 0 读数：`attnbox:notify` localStorage 残留 `off` 会静默关闭整条通知路径（`Notification.permission` 仍 granted），round-221 前两个观察窗因此读到 0——通知探针必须先核实 bell aria-pressed=true（或 notify-ls ≠ off）再信任零读数，跑完还原状态。
- API 反 ack 契约是 `POST /api/ack {id, at: null}`：探针发 `{acked:false}` 会被输入校验拒绝（缺 `at`），"反 ack"静默不生效造成台账残留——round-233 捕获，批量清理走 `{id, at:null}` 循环并核实顶层 acked map 归零。
- 3.4k+ 规模 `ls --all --json` 输出会打爆 execSync 默认缓冲（ENOBUFS，round-265）——探针 shell 出全量 CLI 时必须传大 `maxBuffer`（如 128MB）。
- detached daemon 相对路径按 shell cwd 解析（round-286 一次 MODULE_NOT_FOUND）——`setsid nohup node ...` 起探针 daemon 时 CLI 路径用绝对路径。
- 采集器 fixture 探针（round-428）：Claude 采集器 agent 名是 `claude-code` 非 `claude`（id `claude-code:<sessionId>`）；Codex rollout fixture 必须落 `~/.codex/sessions/YYYY/MM/DD/` 且首行带 `session_meta`（payload.id 提供 sessionId），否则按设计被跳过。
- axe 审计各态必须从未变异页面单独跑：round-410 首轮探针在同页先对 done 态做 DOM 裁剪（`el.remove()` 前 60 卡外）再切 grouped/help，客户端渲染壳失同步产生 landmark-one-main/page-has-heading-one 假阳性——干净分页复测均 0 违规。
- axe 审计 done 标签页后进搜索态要先 reload——done tab 不渲染搜索框，直接 locator 会超时（round-284）。分组态可直接置 `attnbox:group=on` localStorage 后 reload 驱动（round-323：UI toggle 按文本 locator 找不到时用此法）。
- 长活跃会话的探针标签页要每轮收尾关闭：数周探针遗留 ~50 个 localhost/about:blank 标签页会把共享 Chrome 压垮（load 75、单 renderer 1.3GB、kswapd 抖动，round-308 dark 主题首跑卡死）——用 CDP `/json/close` 清空后一分钟内恢复。
- 离线/重连断言不能用全页文本 regex——dogfood 规模下会话卡片文本可能自带 "--offline" 等词造成假阴性（round-297 首跑）——断言 header live/offline pill 与精确横幅文案（"Connection to the attnbox daemon lost"）。离线/PWA 探针基线前必须 `localStorage.clear()` + reload：残留的 `attnbox:filter`/`attnbox:snapshot` 会让基线卡数与冷开快照读数全部失真（round-356 首跑作废）。
- 实机探针要独占端口：round-149 一次误读源于前一探针遗留的同端口第二 daemon——起测前 `pgrep -f "port <N>"` 清场。一次性 shell 起探针 daemon 必须 `setsid nohup ... < /dev/null`，裸 `nohup &` 会随父 shell 死掉造成假 "RSS 0" 读数（round-203/210）——采样前先 `pgrep -f` 核实 PID 存活。
- UX 搜索探针的"惰性 fetch 恰好 1 次"断言必须用户式单次输入（如 pressSequentially）：程序化重复 fill() 会各触发一次 /api/items 造成 2 次读数假象（round-438 首跑）；键盘 j/e 断言前先把焦点移出搜索框（body focus），否则快捷键静默无效。
- slim SSE（round-125）：web 订阅 `/api/events?slim=1`，事件不含 done 项，summary 仍全量；Done tab/搜索/分组/展开器靠 `/api/items` 惰性取 done（`summary.total - items.length` 漂移即失效重取）。改 web 视图逻辑时注意用 `allItems`（含惰性 done）而非 `data.items`。
